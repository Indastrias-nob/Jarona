## 1. Что это за проект

Jarvis — голосовой помощник для Fedora Linux на русском языке. Управляет ПК
(громкость, приложения, медиа, скриншоты), работает с файлами и вводит текст
голосом в активное окно.

**Ключевая архитектура:** простые команды обрабатываются мгновенно офлайн,
сложные уходят в LLM (OpenRouter), которая возвращает JSON с намерением.

```
микрофон → SpeechRecognition (Google) → handle_text_command (офлайн, без сети)
                                              ↓ не распознано
                                        llm.understand() → OpenRouter → JSON
                                              ↓
                                        handle_llm_result → действие
```

## 3. Как запускать

```bash
cd ~/new11
export OPENROUTER_API_KEY=sk-or-...   # без ключа работают только простые команды

python3 jarvis/jarvis.py            # голосовой режим (слово «Джарвис»)
python3 jarvis/jarvis.py --text     # текстовый режим — основной способ отладки
python3 jarvis/jarvis.py --no-tts   # без озвучки
python3 jarvis/jarvis.py --check-llm   # диагностика ключа и модели
python3 jarvis/jarvis.py --list-mics   # список микрофонов
python3 -m unittest discover -s tests  # тесты
```

Тесты запускать **из корня проекта**: `python3 -m unittest discover -s tests`.
Внутри `tests/` работает `python test_jarvis.py`, но `discover` надёжнее.

## 4. Что уже сделано (и проверено вживую)

- **LLM-диспетчеризация.** До этого `understand()` импортировался и никогда не
  вызывался — сложные команды не работали.
- **Слово пробуждения.** Была полностью сломана: обращение к неимпортированному
  `WAKE_WORD` и возврат `None` при найденном слове. Сейчас: варианты
  `jarvis / джарвис / жарвис` с нечётким сравнением (Google часто пишет
  кириллицей), команда может быть сказана сразу после слова.
- **Wayland.** Ввод текста через `wl-copy` + `ydotool`; X11 (`xclip`/`xdotool`)
  поддерживается как fallback.
- **Устойчивость LLM.** Перебор моделей при 429, пауза из заголовка
  `Retry-After`, проверка пустых `choices`/`content`, подстановка `reasoning`
  вместо пустого `content`.
- **Бюджет токенов `LLM_MAX_TOKENS=1200`.** Критично: при 300 токенах
  reasoning-модели тратили бюджет на «мышление» и возвращали рассуждения вместо
  JSON — это была главная причина непонятных ошибок.
- **`response_format: json_object`** для всех моделей; при ответе 400 запрос
  повторяется без этого поля.
- **Терпимый разбор ответа**: JSON ищется в markdown и в тексте вокруг,
  понимаются `True/False/None` и словари в стиле Python.
- **Безопасность**: файловые операции ограничены `ALLOWED_FILE_ROOTS`
  (домашний каталог), выход за пределы блокируется; удаление спрашивает
  подтверждение; команды запускаются без `shell=True`.
- **Проверено живыми запросами**: `привет` → ответ; `открой браузер` → запуск
  firefox; `создай файл ~/rt.py` → файл создан; `напиши в него калькулятор` →
  в `~/rt.py` записан рабочий код (28 строк, `py_compile` проходит);
  `напиши в файл ~/rt2.py факториал` → валидный Python.

## 5. Что НЕ проверено (требует интерактивной сессии)

Отмечайте это в отчётах: статическая проверка ≠ работоспособность.

- **Голосовой режим целиком** — микрофон и распознавание не запускались
  ни разу за сессию (нет доступа к аудио из неинтерактивной оболочки).
- **Вставка текста через `ydotool`** — написан код, не проверен. У `ydotool`
  бывают проблемы с правами на `/dev/uinput`; проверить в реальном сеансе:
  `ydotool key 29:1 47:1 47:0 29:0` (Ctrl+V) и посмотреть, не требует ли демон
  `ydotoold` и udev-правило.
- **Слово пробуждения** — логика покрыта юнит-тестами, но с живым микрофоном
  и реальным распознаванием не проверялось.
- **Скриншот** — `gnome-screenshot` в неинтерактивной сессии зависает (таймаут
  30 с). В реальном сеансе должен работать; при проблемах добавить `grim`.
- **TTS** — `espeak-ng` выбран первым, но звук не слушали.

## 6. Известные ограничения

- **Список окон на Wayland недоступен** — `xdotool` нет; возвращается пустой
  список с сообщением. Если нужно — смотреть в сторону `wlr-foreign-toplevel`
  (только для wlroots) или `gdbus` к GNOME Shell (требует расширения).
- **Бесплатные модели OpenRouter нестабильны.** `google/gemma-*:free` постоянно
  отдаёт `429 rate-limited upstream`. Рабочие на момент проверки:
  `minimax/minimax-m3.1-flash:free` (основная),
  `poolside/laguna-s-2.1:free`, `dots-studio/dots-3-note-preview:free`.
  Список бесплатных моделей меняется — проверять:
  `curl -s https://openrouter.ai/api/v1/models | grep ':free'`.
- **Модели без поддержки `response_format`** обрабатываются повтором без поля,
  но такой повтор расходует одну попытку.
- **История диалога** хранится в `dialogue.json`, максимум 10 сообщений.
- **Ключ API пользователь засветил в переписке** — рекомендовано перевыпустить.

## 7. Следующие шаги (по приоритету)

### 7.1 Переключение на «умную» модель — главная задача

Пользователь готовит презентацию и хочет показать ассистента на более сильной
модели. Проект **уже** поддерживает это без правок кода — через переменную
окружения или переменную в `config.py`:

```bash
# вариант 1: разово, перед показом
export OPENROUTER_MODEL=anthropic/claude-sonnet-5.5

# вариант 2: постоянно — в jarvis/config.py
OPENROUTER_MODEL = os.environ.get("OPENROUTER_MODEL", "anthropic/claude-sonnet-5.5")
```

Актуальные цены на OpenRouter (проверено 2026-10-21, $/млн токенов, вход/выход):

| Модель (slug OpenRouter) | Цена | Комментарий |
|---|---|---|
| `anthropic/claude-haiku-5.5` | 0.10 / 0.50 | самая дешёвая Claude, 1M контекста |
| `anthropic/claude-sonnet-5.5` | 2.00 / 10.00 | **разумный выбор для презентации** |
| `anthropic/claude-opus-5.5` | 4.00 / 20.00 | максимальное качество |

Бесплатные, но с лимитами: `google/gemma-*:free` (часто 429),
`minimax/minimax-m3.1-flash:free`.

**Что нужно сделать при смене модели:**
1. Проверить, что ключ OpenRouter имеет положительный баланс — бесплатные
   модели не требуют денег, платные требуют.
2. Убедиться, что `OPENROUTER_FALLBACK_MODELS` не подменяет платную модель
   бесплатной при сбое (сейчас в списке есть `google/gemma-4-31b-it:free`).
3. Прогнать `--check-llm`, затем сценарий презентации руками.
4. Проверить, что платная модель поддерживает `response_format`.

### 7.2 Проверить голосовой режим вживую

Самое важное перед презентацией: ни разу не проверялось. Запустить
`python3 jarvis/jarvis.py`, сказать «Джарвис, открой браузер», убедиться, что
`ydotool` вставляет текст в активное окно.

### 7.3 Возможные доработки

- Список окон на Wayland (см. ограничения выше).
- Задержка: каждый голосовой запрос идёт в сеть; для презентации можно
  кэшировать частые фразы или расширить офлайновые команды.
- Диалоговая память сейчас 10 сообщений — при показе сценария с контекстом
  («создай файл», потом «напиши в него») этого достаточно.

## 8. Соглашения проекта

- Код, комментарии и сообщения коммитов — **на русском**.
- В сообщениях коммитов **не должно быть** строк вида `Co-Authored-By:` и
  упоминаний ИИ-генерации — пользователь просил их удалить.
- Стиль: docstrings на русском, запуск внешних программ через список
  аргументов (без `shell=True`), ошибки логируются и не роняют ассистента.
- Перед коммитом: `python3 -m py_compile jarvis/*.py` и
  `python3 -m unittest discover -s tests`.
- Тесты держать быстрыми и без сети (LLM мокается через `unittest.mock`).
