# Jarvis — голосовой помощник для Linux (Fedora)

Голосовое управление ПК на русском языке: понимание команд через LLM
(OpenRouter), управление громкостью, приложениями, медиа, файлами, скриншоты
и голосовой ввод текста в активное окно.

## Быстрый старт

```bash
# Python-зависимости
python3 setup.py          # или: pip install -r requirements.txt

# Системные утилиты (Fedora)
sudo dnf install espeak-ng wl-clipboard ydotool playerctl grim

# API-ключ OpenRouter (https://openrouter.ai)
export OPENROUTER_API_KEY=sk-or-...

python3 jarvis/jarvis.py
```

## Режимы запуска

| Команда | Что делает |
|---|---|
| `python jarvis/jarvis.py` | голосовой режим, команды после слова «Джарвис» |
| `--no-wake` | слушать команды без слова пробуждения |
| `--text` | текстовый режим (без микрофона), удобно для отладки |
| `--no-tts` | не озвучивать ответы |
| `--mic N` | выбрать микрофон (индекс или часть имени) |
| `--list-mics` | показать доступные микрофоны |
| `--check-llm` | проверить доступность OpenRouter и выйти |
| `-v` | подробный лог (`~/.local/share/jarvis/jarvis.log`) |

## Как это работает

1. Микрофон → Google Speech Recognition (или локальный Whisper, если установлен).
2. Простые команды («громче», «скриншот», «пауза») обрабатываются мгновенно,
   без обращения к сети — см. `handle_text_command` в `jarvis/jarvis.py`.
3. Всё остальное уходит в LLM, которая возвращает JSON
   `{"intent": ..., "args": {...}, "answer": "..."}`; результат исполняется
   в `handle_llm_result`.
4. Ответы озвучиваются через espeak-ng (fallback: gTTS, затем консоль).

## Примеры команд

- «Джарвис, открой браузер»
- «громкость 40», «громче», «тише», «выключи звук»
- «найди в интернете рецепт борща»
- «скриншот», «что открыто», «пауза», «следующий трек»
- «создай файл ~/заметки.txt»
- «напиши в файл ~/calc.py калькулятор на питоне» — код пишется в файл
- «прочитай файл ~/calc.py»
- «открой папку ~/Загрузки»
- «сделай текст заглавными ~/заметки.txt»
- «слушай» — голосовой ввод текста в активное окно (скажите «стоп» для конца)

## Безопасность

- Файловые операции ограничены каталогами из `ALLOWED_FILE_ROOTS`
  (по умолчанию — домашний каталог); выход за пределы блокируется.
- Удаление файлов требует подтверждения (`CONFIRM_DELETE`).
- Команды выполняются без `shell=True` — инъекции через текст не работают.

## Структура проекта

```
jarvis/
  jarvis.py       — точка входа, диспетчеризация команд
  config.py       — настройки (переопределяются переменными окружения)
  recognition.py  — микрофон, распознавание речи, слово пробуждения
  llm.py          — OpenRouter, разбор JSON-намерений
  pc_control.py   — громкость, приложения, окна, скриншоты, медиа
  file_ops.py     — файловые операции с проверкой путей
  voice_input.py  — голосовой ввод текста в активное окно
  tts.py          — синтез речи
  context.py      — история диалога для LLM
  profile.py      — профиль пользователя
tests/
  test_jarvis.py  — тесты (python3 -m unittest discover -s tests)
```

## Настройка

Настройки лежат в `jarvis/config.py`. Часто нужные можно задать через окружение:

| Переменная | Значение |
|---|---|
| `OPENROUTER_API_KEY` | ключ OpenRouter |
| `OPENROUTER_MODEL` | модель (по умолчанию `minimax/minimax-m3.1-flash:free`) |
| `JARVIS_MIC` | микрофон (индекс или часть имени) |
| `JARVIS_DATA_DIR` | каталог данных (по умолчанию `~/.local/share/jarvis`) |
| `JARVIS_TTS` | `auto` / `espeak` / `gtts` |

## Модели и устойчивость к сбоям

Бесплатные модели OpenRouter часто отдают `429 Too Many Requests`. Jarvis:

- повторяет запрос с паузой (учитывает заголовок `Retry-After`);
- перебирает резервные модели из `OPENROUTER_FALLBACK_MODELS`;
- отвечает «Сервис распознавания перегружен, попробуйте через минуту» вместо
  непонятной ошибки.

Дополнительно Jarvis защищён от «болтливых» моделей, которые вместо JSON пишут
рассуждения:

- запрашивается строгий режим `response_format: json_object` (при отказе модели
  запрос повторяется без него);
- бюджет ответа `LLM_MAX_TOKENS` повышен до 1200 — reasoning-модели тратят
  токены на «мышление» и при малом лимите не успевают выдать JSON;
- ответ разбирается терпимо: JSON ищется в markdown-блоке и в тексте вокруг,
  понимаются `True/False/None` и словари в стиле Python;
- если в модели сломан разбор — ответ честно сообщает «не удалось понять
  команду», а не «нет связи».

Модель по умолчанию — `minimax/minimax-m3.1-flash:free`; резервные —
`poolside/laguna-s-2.1:free`, `dots-studio/dots-3-note-preview:free`,
`google/gemma-4-31b-it:free`. Если модель не отвечает или возвращает пустой
ответ, она пропускается. Проверить связку целиком:

```bash
python3 jarvis/jarvis.py --check-llm
```

Список бесплатных моделей меняется — посмотреть актуальные:
`curl -s https://openrouter.ai/api/v1/models | grep ':free'`.


## Требования

Python 3.10+. Wayland и X11 поддерживаются. Для вставки текста на Wayland
нужен `ydotool` (работает через uinput; может потребоваться udev-правило
`uinput` и запуск от пользователя в группе с доступом к `/dev/uinput`).
